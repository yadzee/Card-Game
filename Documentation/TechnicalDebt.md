# Technical Debt — технический долг и вопросы проверки

**Статус:** реестр наблюдений по статическому обзору. Ничего из перечисленного не следует автоматически считать подтверждённым runtime-дефектом.

Уровни:
- **P1** — потенциально влияет на корректность/безопасность основного игрового цикла.
- **P2** — риск сопровождения или вероятная проблема прототипа.
- **P3** — уборка/качество проекта.

## Тестовые клавиши — оставить на текущем этапе

В `Player.Update()` и `CombatController.Update()` присутствуют тестовые клавиши для отладки боя, энергии, блока и карт.

**Решение пользователя:** тестовые клавиши пока нужны для разработки. Не удалять и не переносить их в рамках обычных задач. Позже можно отдельно решить, как ограничить их Editor/debug-режимом перед выпуском билда.

## DeckViewer — не технический долг

`DeckViewer` находится в процессе разработки и пока не завершён. Его текущее состояние описано в `ProjectStatus.md`. Не регистрировать его как дефект только из-за незавершённости и не менять систему рендеринга без проверки фактического поведения и требований задачи.

## P2 — Bootstrap и запуск приложения

`GameStartup.Start()` использует `SceneManager.LoadScene(1)`. Сейчас индекс соответствует `CardScene` при текущем Build Settings.

**Решение пользователя:** bootstrap будет отдельной задачей; текущую реализацию пока не менять.

**План:** при работе над bootstrap пересмотреть стартовую сцену, инициализацию приложения и переходы между сценами. В том числе решить, заменить ли индекс `1` на имя сцены или централизованную конфигурацию.

## P2 — дублирующая/альтернативная UI-награда

В проекте присутствуют `Gameplay.Rewards.RewardUI` и `UI.RewardPanelUI`; в `CardScene` обнаружен `RewardUI`, а `RewardPanelUI` там не найден.

**Предварительное решение пользователя:** вероятно, это старая лишняя реализация.

**План:** отдельной задачей проверить usages, prefab/scene references и назначение класса. Если подтверждено, что он нигде не используется, удалить реализацию и связанные неиспользуемые ассеты.

## P2 — null guards и сериализованные ссылки

В статическом обзоре отмечены места, предполагающие заполненные ссылки:
- `DeckViewer.ShowDrawPile()` обращается к `deck.DrawPile` до null-check;
- `DeckViewer.Close()` обращается к `viewerPanel`;
- `PlayerHandUI.Awake()` подписывается на зависимости;
- UI здоровья/энергии и `UiCardLink.Initialize()` используют сериализованные ссылки.

**Риск:** ошибка при неполной настройке сцены/префаба.

**Проверить:** сопоставить все ссылки с Inspector в активных сценах и префабах. Не добавлять null-check механически: сначала определить, является ли ссылка обязательной и как должен вести себя компонент при её отсутствии.

## P3 — тестовые и шаблонные ресурсы

В репозитории обнаружены:
- `Assets/_Recovery`;
- примеры TextMesh Pro;
- тестовые скрипты/сцены;
- `Assets.zip`.

**Проверить:** какие ресурсы реально нужны, какие попали в билд, что используется ссылками. Удаление — отдельной задачей с проверкой GUID и references.

## StrongEnemy — оставить в проекте

`StrongEnemy` сейчас используется как тестовый объект. Пользователь подтвердил, что в дальнейшем в игре будут сильные противники и боссы.

**Решение:** объект/класс не считать лишним и не удалять. Текущую сцену менять не требуется.

## P3 — DefaultVolumeProfile

В `DefaultVolumeProfile.asset` обнаружены компоненты с `m_Script: {fileID: 0}`. При этом `CardScene` использует `SampleSceneProfile`.

**Гипотеза:** повреждённый/неиспользуемый шаблонный профиль, не участвующий в активной сцене.

**Проверить:** ссылки на профиль и использование в других сценах/настройках.

## P2 — постепенный переход на новый Input System

В проекте используются legacy `UnityEngine.Input` и новый Input System; `activeInputHandler: 2`.

**Согласованное решение:** целевое направление — новый Input System. Переход отложен на отдельную задачу.

**План:** перед миграцией составить список legacy-вызовов, проверить UI input module и существующие Input Actions, затем переносить ввод небольшими проверяемыми этапами. Не начинать миграцию попутно с несвязанными задачами.

## Что не проверено

- Полное runtime-поведение всех сцен.
- Все сериализованные ссылки каждого префаба и сцены.
- Все 130 C#-файлов построчно.
- Все `.meta` и GUID-ссылки.
- Сборка проекта и тесты в Unity Editor.
- Профили производительности и платформенные билды.

Этот реестр не является списком обязательных исправлений. Сначала воспроизвести и оценить влияние.
