## 1. Кратко

Проект — карточный roguelike на Unity. Основной текущий фокус — развитие игрового цикла одного боя: бой → победа → выбор награды → управление колодой. Непосредственная точка продолжения разработки — незавершённый `DeckViewer`.

Последние изменения в GitHub показывают развитие:
- потока наград после завершения боя;
- UI завершения хода;
- просмотра колоды и инспекции стопок;
- Deck Viewer в `CardScene`.

Это описание следует сверять с текущей локальной рабочей копией.

## 3. Известные реализованные системы

- Данные карт через `CardData` ScriptableObject.
- Runtime-класс `Card`.
- Эффекты урона, блока и уязвимости.
- Колода с draw pile, discard pile и hand.
- Рука игрока и визуальная система карт `UICard`.
- Пошаговый бой, энергия, здоровье, блок и намерения противника.
- Механика `RumCup`.
- Завершение боя и поток выбора награды.
- Начатая, но незавершённая реализация UI просмотра колоды/стопок (`DeckViewer`).
- Card Editor с созданием карт и live preview.

Степень готовности отдельных функций и наличие edge-case обработки не подтверждены только фактом присутствия классов/коммитов.

## 4. Последняя завершённая пользовательская проверка

Пользователь ранее подтвердил в Play Mode корректную сортировку модульной карты:
- карты перекрываются в руке корректно;
- hover выводит карту на передний план;
- после hover исходный порядок восстанавливается;
- внутренняя композиция не ломается.

Эта проверка относится к более раннему этапу. После последующих изменений нужно повторить smoke test, если затрагивается визуальная система.

## 5. Текущая задача: завершить DeckViewer

**Статус:** в разработке, не завершено.  
**Приоритет:** ближайшая задача при продолжении работы через Codex.

Работа над `DeckViewer` была начата в предыдущей сессии и остановилась на полпути. Последние связанные изменения добавили UI просмотра колоды/стопок и подключили DeckViewer к `CardScene`.

Правила продолжения:
1. Сначала изучить актуальные версии всех связанных скриптов, префабов и `CardScene`.
2. Проверить последние связанные Git-коммиты и понять, какие изменения уже внесены.
3. Установить, что уже работает, что не работает и что осталось реализовать. Не додумывать незавершённые требования.
4. Не создавать новую систему просмотра колоды параллельно существующей.
5. Не переписывать существующую реализацию без конкретной причины.
6. Сформулировать ближайший небольшой шаг и проверить его в Unity.

Сочетание Overlay Canvas и рендереров в `CardDisplayView` ранее было отмечено только как статическое наблюдение. Это не подтверждённый дефект и не основание для самостоятельной переделки. Проверять его нужно в контексте фактической задачи DeckViewer.

## 6. Согласованные решения и будущие задачи

Последняя задача из исторического документа от 02.11.2026 — подключение индивидуальных иллюстраций карт через `CardData.Sprite`. Однако последующий аудит репозитория обнаружил, что `UiCardLink.Initialize(Card)` уже назначает спрайт через `_texturePicker.SetSprite(card.Sprite)`. Поэтому старую задачу нельзя считать актуальной без проверки текущего кода и визуального результата.

Согласованные решения:
1. **Input System:** целевое направление — постепенный переход на новый Input System. Выполнить отдельной задачей; до неё не трогать существующую схему без необходимости.
2. **CombatController:** пока остаётся координатором боевого процесса. Рефакторинг отложен до появления конкретной необходимости.
3. **StrongEnemy:** сейчас тестовый объект, но в будущем проекту нужны сильные противники и боссы. Оставить; ничего не удалять.
4. **RewardPanelUI:** вероятно, старая лишняя реализация. В отдельной задаче проверить usages/references и удалить, если она действительно нигде не используется.
5. **Bootstrap:** запуск приложения и переходы между сценами будут отдельной задачей. До неё не менять `GameStartup` попутно.
6. **Тестовые клавиши:** пока нужны для разработки. Оставить.

Оставшиеся вопросы проверки:
- `DeckViewer`: корректно ли отображаются карты/стопки при сочетании Overlay Canvas и SpriteRenderer/MeshRenderer?
- Какие ресурсы из `_Recovery`, TMP Examples и `Assets.zip` действительно нужны?
